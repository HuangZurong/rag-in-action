# 40 分钟精品试讲讲稿与演示手册

## 课程信息
- 课程主题：生产可用 RAG 核心原理与失败驱动优化
- 试讲时长：40 分钟
- 核心案例：Amazon 欧洲站跨境客服知识助手
- 听众目标：理解 RAG 机制、看懂检索失败根因、掌握针对性优化选型、建立评测闭环。

---

## 阶段一：LLM 边界与 RAG 的本质（00:00 - 08:00）

### 1. 讲师开场（2 分钟）
- **专家立威话术**：“大家下午好。市面上 90% 的教程都在教大家用‘Embedding + 向量库 + LLM’三板斧快速跑通一个 Demo。但在真实的跨境电商或工业生产环境里，这种玩具 Demo 上线第一天就会出事：
  - 如果买家问：‘德国站买了一款带电池的智能设备，第 20 天坏了，运费谁出？’
  - Demo 会由于语义相似，精准检索出 2023 年已废止的旧政策，导致赔付纠纷；或者检索到英国站规则，给出错误的物流标签导致海关扣关。
  今天我们不讲网上的三板斧玩具，我们站在**工业级 AI 生产落地**的视角，看看一个真正高可用、可溯源、抗干扰的 RAG 工业系统到底该怎么建。”
- **板书/幻灯片**：
  - 基础模型：参数化知识（静态、无私有数据、无版本控制、无法溯源）
  - 业务需求：确定性政策（动态更新、分站点、分品类、有法律责任）

### 2. 方案对比与 RAG 起点（4 分钟）
- **推导**：
  - 微调（Fine-tuning）：不适合高频变动的政策，训练成本高，且无法彻底消除幻觉。
  - 全部塞入 Prompt（Long Context）：成本高、延迟长，且当知识库达到几万份文档时无法全量塞入。
  - 结论：把“存储与检索知识”和“理解与生成回答”拆开。
- **公式**：
  $$\text{Answer} = \text{LLM}(\text{Query}, \text{Retrieved\_Context})$$

### 3. 亮出核心原则（2 分钟）
- **强调**：“RAG 的核心首先是 **Information Retrieval（信息检索）**，而不是生成。检索给到垃圾 Context，模型参数再大也只能输出精致的废话。”

## 阶段二：最小 RAG 链路现场演示（08:00 - 18:00）

### 1. 概念拆解（4 分钟）
- 文档（DOC） $\to$ 切块（Chunk） $\to$ 向量化（Embedding） $\to$ 向量库（Vector Index） $\to$ Top-K 检索 $\to$ Prompt 组装 $\to$ LLM 生成。
- 二维示意：Embedding 把文本语义映射到空间坐标，用余弦相似度计算距离。

### 2. 跑通基线 Q1（6 分钟）
- **输入问题**：“德国站买家买了一件普通商品，签收第 20 天因为不喜欢想退货，运费谁出？”
- **展示检索结果**：命中 `DOC-001`（德国站通用退换货政策 2026 版），相似度 0.88。
- **展示生成的 Prompt**：系统指令 + 约束说明 + DOC-001 片段 + 用户问题。
- **模型输出**：“根据 Amazon.de 政策，买家在 30 天退货期内；非质量问题的退货运费由买家自行承担。”
- **效果**：首个基线成功，听众建立完整流程认知。

## 阶段三：制造失败——为什么“相似”不等于“正确”（18:00 - 28:00）

### 1. 抛出主问题 Q2（3 分钟）
- **输入问题**：“德国买家购买了一款含内置锂电池的智能手表，签收第 20 天出现无法开机故障，想退货。商品已经拆封，退货运费谁出？包装有什么要求？”

### 2. 展示检索失败现场（5 分钟）
- 纯向量检索（Top-3）返回：
  1. `DOC-004`（2023 废止版）：相似度 0.89（因为大量包含“德国”、“退货”、“已拆封”、“质量问题”关键词）
  2. `DOC-003`（英国站 2026 版）：相似度 0.84（因为包含“质量问题卖家承担”、“退货标签”）
  3. `DOC-002`（德国站电池限制 2026 版）：相似度 0.81（包含“电池鼓包”、“严禁寄回”）
- **真正最核心的当前版 DOC-001 被挤到了第 4 位！**
- **模型根据错误 Context 生成的离谱回答**：
  > “根据政策，超过 14 天必须先送指定维修点检测；已拆封扣 15% 包装费；请提供 Royal Mail 标签；电池鼓包严禁寄回。”

### 3. 深度剖析（2 分钟）
- **指出三大硬伤**：
  - **版本混淆**：废止政策比当前政策更“字面匹配”。
  - **站点混淆**：不同国家的退货规则语义极度相似，向量距离极近。
  - **条款误用**：把“电池鼓包”的特例安在了“普通故障”上。
- **结论**：“单纯依靠 Embedding 相似度，无法感知版本状态、适用站点和细粒度业务逻辑！”

## 阶段四：针对性优化与问题技术地图（28:00 - 35:00）

### 1. 现场引入针对性优化（4 分钟）
- **第一步：Metadata Pre-filtering（元数据预过滤）**
  - 在检索前强制附加条件：`status == 'active' AND marketplace == 'Amazon.de'`
  - 效果：直接剔除 `DOC-004`（废止）与 `DOC-003`（英国站）。
- **第二步：Reranker（二次重排）**
  - 从过滤后的候选集中召回 Top-10，使用 Cross-Encoder Reranker 针对 Query 重新打分。
  - 效果：`DOC-001` 与 `DOC-002` 稳居前 2 位。
- **第三步：Context Repacking（上下文装箱与排布）**
  - **破解 Lost in the Middle**：采用 **Reverse（反向升序）** 将最高分文档紧贴末尾 Query 注入，并做 Adjacent Chunk Merging 切片缝合与 XML 严格标签包裹。
- **展示修复后的正确答案**：
  > “1. 属于 30 天内质量问题，由卖家承担退货运费；\n2. 已拆封不影响因质量问题退货；\n3. 内置锂电池退货须使用原包装或带 UN3481 标签的合规包装寄回。”

### 2. 引出“问题 $\to$ 技术”全景地图（3 分钟）

| 业务问题 / 失败表现 | 根因分类 | 针对性高级技术 | 引入时机 |
|---|---|---|---|
| 多系统混杂（查退货率走 ChatBI，查退货规则走 RAG）及多轮省略提问 | 缺乏入口意图语义分流与会话上下文状态维护 | **Semantic Router + 多轮指代消解** | 多业务系统路由与复杂多轮对话入口必用 |
| 混淆已作废版本、跨国家站点规则 | 结构化约束缺失 | **Metadata Filtering（元数据过滤）** | 知识库有明确属性（时间/版本/租户）时必选 |
| 行业专有名词（如 UN3481/SKU）搜不到 | 向量对专有名词稀疏特征不敏感 | **Hybrid Search（BM25 + Dense 混合检索）** | 存在型号、错误码、专有编号时 |
| 粗排候选多但前排排序错乱 | Bi-Encoder 交互能力弱 | **Cross-Encoder Rerank（重排）** | 召回结果相关性不足、上下文窗口有限时 |
| 检索命中但大模型漏看核心依据 | Lost in the Middle 注意力黑洞 | **Context Repacking（Reverse 排布+切片缝合）** | 喂给 LLM 的长上下文组装阶段必用 |
| 用户提问口语化、少关键信息 | Query 与文档表达不匹配 | **Query Rewrite / Multi-Query** | 真实多轮对话或模糊提问场景 |
| 跨多份文档的关系推理与归纳 | 独立切块切断了实体关系链 | **Graph RAG / 知识图谱** | 需要跨实体、跨文档做全局总结或推理时 |
| 需要多步决策（查政策 $\to$ 查订单 $\to$ 算运费） | 单次单向检索无法完成复合任务 | **Agentic RAG（智能体 RAG）** | 需要调用工具、动态循环检索并验证答案时 |

## 阶段五：高级评测体系与生产闭环（35:00 - 40:00）

### 1. 专家的评测解耦哲学：RAG Triad（2 分钟）
- **话术**：“在工业级体系里，调优绝不能‘凭感觉’。如果你只看最终答案通不通顺，就像蒙着眼睛修发动机。
  我们必须将系统严格拆解为**双循环评测（RAG Triad）**：
  1. **Context Relevance（检索相关性）**：检索到的切片到底有没有答题所需的信息？（指标看 Recall@K、MRR、NDCG@K）
  2. **Groundedness / Faithfulness（事实忠实度）**：答案中的每一个原子断言，是否 100% 来源于 Context，有没有私自脑补？（指标必须 100%）
  3. **Answer Relevance（答案契合度）**：有没有答非所问、有没有绕弯子废话？
  通过这三个维度的正交拆解，我们才能秒级定位问题到底出在【切块/检索】还是【Prompt/模型】。”

### 2. 用量化门禁数据说话与 CI/CD 数据飞轮（2 分钟）
- 展示回归结果对比表：
  - **Naive RAG（纯向量）**：Recall@3 = 60%, NDCG@3 = 0.52, Faithfulness = 50%, 废止版本泄露率 = 40%
  - **Industrial RAG（Metadata+Rerank）**：Recall@3 = 100%, NDCG@3 = 0.96, Faithfulness = 100%, 废止版本泄露率 = 0%
- **点出工业级数据飞轮**：
  - “在线上，我们通过 Phoenix / OpenTelemetry 挂载全链路 Trace，实时监控线上 Bad Case（如用户点踩、低置信度召回），自动清洗并回流到测试集，形成持续演化的 **CI/CD 自动化评测门禁**。”

### 3. 结课收束与全景延伸（1 分钟）
- **专家收尾金句**：“今天我们以一个跨境电商案例为切口，见证了一个 RAG 系统从‘玩具跑通’到‘工业可用’的完整蜕变。真正的工业级 AI，拼的不是调包的速度，而是对数据前置治理的深度、对混合检索与重排的掌控力、以及严密的量化评估闭环。接下来的课程，我们将逐一攻克这些模块。谢谢大家！”
