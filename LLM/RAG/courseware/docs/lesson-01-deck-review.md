## P03: 业务场景与角色

- **大字**：`知识库到底给谁用？解决什么问题？`
- **4 个场景卡片**：
  1. **商品中心**：查询商品规格、面料参数、SKU 信息（如：SKU-YG301 瑜伽裤面料是什么？）
  2. **合规风控**：查询 FTC 法规、退货政策、检测标准（如：冲锋衣能不能标 Waterproof？）
  3. **尺码客服**：查询美码对照表、版型差异、Inseam 数据（如：女款 Regular 腰围多少？）
  4. **店铺运营**：查询运营政策、Listing 规范、季节性要求（如：Q4 退货政策延长到多久？）

## P04: 大模型两大硬伤

- **大字**：`直接问大模型，必然在这两个地方翻车。`
- **左右对比**：
  - **左：知识过时** → 大模型训练数据有截止日期；亚马逊退货政策、FTC 法规每季都在变，模型根本不知道最新规则。
  - **右：私有知识缺失** → 大模型训练集里没有你企业的质检单、打样报告、SKU 规格表；问它 SKU-JK902 的面料参数，它只能瞎猜。
- **底部对比**：微调太贵太慢，长上下文太贵还会漏看（Lost in the Middle），都不如 RAG 直接接知识库。

---

## P05: 什么是 RAG？（大白话）

- **大字**：`什么是 RAG？就是给大模型配一个专属资料员。`
- **左右对比**：
  - **左：没有 RAG** → 考生没带书进考场，遇到不会的题只能凭记忆瞎编（幻觉）。
  - **右：有 RAG** → 考生带了专属资料员，遇到不会的题先翻资料找答案，再组织语言回答。

---

## P06: 大模型的职责

- **大字**：`有了资料员，大模型到底干什么？`
- **4 项职责**：
  1. **理解问题**：搞清楚用户到底在问什么；
  2. **抽取证据**：从检索回来的资料中提取关键信息；
  3. **逻辑推理**：基于证据做推理判断；
  4. **组织答案**：把推理结果组织成通顺的回答。
- **底部**：`检索系统的职责只有一个：精准找到相关资料。`

## P07: RAG 标准流水线

- **大字**：`RAG 标准流水线全景`
- **三段式流程图**：
  1. **离线建库**：Document → Chunking → Embedding → Vector DB
  2. **在线检索**：Query → 向量化 → Top-K 检索 → 召回结果
  3. **组装生成**：检索结果 + Prompt → 大模型 → 回答

## P08: 实战：瑜伽裤选品

- **大字**：`3 步跑通：瑜伽裤 (SKU-YG301) 选品实操`
- **步骤**：
  1. 离线建库：把商品知识库切分、向量化、入库；
  2. 在线检索：问"SKU-YG301 面料规格" → Top-K 检索命中质检单；
  3. 生成回答：命中 75% Nylon 66 + 25% Lycra, 230 GSM, Squat-Proof。

## P09: 代码实现

- **大字**：`LangChain LCEL 声明式链：几行代码跑通 RAG`
- **代码展示**：
  ```python
  retriever = vector_db.as_retriever(search_kwargs={"k": 5})
  rag_chain = (
      {"context": retriever | format_docs, "question": RunnablePassthrough()}
      | prompt
      | llm
  )
  result = rag_chain.invoke("SKU-YG301 面料规格")
  ```
- **底部**：`retriever | format_docs | prompt | llm —— 一条链串起检索与生成。`

## P10: 向量相似度

- **大字**：`向量检索：把文字变成坐标，算距离找最近。`
- **核心内容**：
  - 文本 → Embedding → 高维向量坐标；
  - 余弦相似度计算两个向量的"方向"是否接近；
  - 示例：瑜伽裤查询向量与质检单向量余弦相似度 0.89 → 秒级命中。

## P11: 纯向量翻车：货号搜不到

- **大字**：`但是货号、专有编码搜不到。`
- **翻车场景**：
  - 搜 `SKU-JK902`、`Cordura 500D`、`YKK 8#` → 纯向量检索把核心切片排到第 40 名；
  - 原因：向量模型做子词切分，`SKU-JK902` 被拆成碎片，语义被稀释；专有编码在全库里是唯一的，但向量"平滑"了这个差异。

---

## P12: 混合检索救场

- **大字**：`BM25 + 向量混合检索：两种方式互补。`
- **核心内容**：
  - **BM25（稀疏检索）**：倒排索引 + IDF，专有编码全库唯一，IDF 分数爆表，一招置顶；
  - **Dense（向量检索）**：擅长"意思相近"，适合自然语言查询；
  - **RRF 融合**：两路结果按排名倒数加权融合，取长补短；
  - **实操验证**：同样的货号查询，混合检索后核心切片回到 Top-3。
- **底部**：`混合检索是 RAG 入门标配，不是高级技巧。`

---

## P13: 裸答 vs RAG 同屏对比

- **大字**：`同一个问题，没 RAG 和有 RAG 差多大？`
- **左右对比**：
  - **左：大模型裸答** → "冲锋衣 SKU-JK902 防水等级？" → 瞎猜"标准防水" ❌（实际需 AATCC 127 测试）
  - **右：RAG 回答** → 同样问题 → 检索到质检单 → "AATCC 127 静水压 15,000mm，可标 Waterproof" ✅

## P15: 小结与第 2 课预告

- **大字**：`RAG 入门搞定，但真实数据远没有这么干净。`
- **小结**：
  - RAG 的本质是解耦：推理归模型，知识归检索；
  - 纯向量不够用，混合检索（BM25 + Dense + RRF）是入门标配；
- **第 2 课预告**：
  - 混合检索解决了货号搜不到，但如果检索回来的文档里有旧政策混在新政策里、男款尺码表串到女款查询里，怎么办？
