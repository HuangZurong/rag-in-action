# 第 1 课：RAG入门 —— 为什么有了LLM还需要RAG？（40 分钟）

> **本课目标**：看清大模型的知识边界，理解为什么微调和长上下文救不了动态业务，掌握 RAG 的解耦原理，跑通最小 RAG 并引入混合检索。

### 1. 从一个真实问题开始：选品经理问大模型（00:00 - 08:00）
- **场景**：亚马逊美国站选品经理要调研 2026 秋冬冲锋衣（SKU-JK902），直接拿业务问题问大模型：
  - "SKU-JK902 的静水压测试结果是多少 mm？能不能标 Waterproof？" → 大模型不知道这批面料的具体质检报告，只能猜；
  - "SKU-JK902 女款收腰版 38 码的胸围和腰围分别是多少英寸？" → 大模型训练集里没有这个刚打样的版型数据，给了通用男码数据，买家按男码买女款；
  - "我们公司 2026 Q4 的退货政策截止日期是哪天？" → 大模型不知道你公司当季的最新运营政策，只能套通用规则；
- **问题在哪**：这些问题的答案都不在大模型的训练集里——质检报告是内部的、版型数据是刚出的、运营政策是随时变的；
- **核心设问**：为什么千亿参数的大模型，在具体业务问题上会这么不靠谱？

### 2. 机制剖析：大模型两大硬伤（08:00 - 16:00）
- **硬伤一：知识时效盲区**
  - 权重参数在预训练结束时冻结；商业规则、季节、法规每分每秒都在变；
- **硬伤二：企业私有知识缺失**
  - 缺乏 AATCC 127 静水压、230 GSM 经编、Inseam 矮版 28" 等精确参数；
  - 大模型训练集里根本没有你企业的内部质检单和打样报告；
- **为什么其他方案走不通？**
  - 微调：上新快、成本高、时效滞后、灾难性遗忘；
  - 长上下文：Token 成本高、首字延迟、Lost in the Middle 漏看。

### 3. 解耦原理：开卷考试（16:00 - 22:00）
- **本质**：逻辑推理（大模型）与知识存储（外部检索系统）分离；
- **大白话**：大模型是没带书进考场的考生，RAG 就是给它配一个专属资料员；
- **大模型的职责**：理解问题、从资料中抽取证据、逻辑推理、组织答案；
- **检索系统的职责**：精准找到相关资料。

### 4. 最小 RAG 跑通：瑜伽裤选品实战（22:00 - 30:00）
- **离线建库**：Document → Chunking → Embedding → Vector DB；
- **在线检索与生成**：Query → 向量化 → Top-K 检索 → Prompt 注入 → 大模型生成；
- **实操验证**：提问瑜伽裤（SKU-YG301）面料规格 → 命中 75% Nylon 66 + 25% Lycra, 230 GSM；
- **代码实现**：LangChain LCEL 声明式链写法。

### 5. 纯向量的局限与混合检索引入（30:00 - 38:00）
- **翻车再现**：搜 `SKU-JK902`、`Cordura 500D`、`YKK 8#`，纯向量检索因为子词切分和高维平滑，核心切片排到第 40 名；
- **直觉解释**：向量检索擅长"意思相近"，但不擅长精确匹配货号和专有编码；
- **BM25 救场**：倒排索引 + IDF，专有编码全库唯一，IDF 分数爆表，一招置顶；
- **混合检索**：BM25（稀疏）+ Dense（向量）双路召回，RRF 融合排序，两种优势互补；
- **实操验证**：同样的货号查询，混合检索后核心切片回到 Top-3。

### 6. 本课小结与第 2 课预告（38:00 - 40:00）
- **小结**：RAG 的本质是解耦（推理归模型，知识归检索）；纯向量不够用，混合检索是入门标配；
- **悬念**：混合检索解决了货号搜不到的问题，但如果检索回来的文档里有旧政策混在新政策里、男款尺码表串到女款查询里，该怎么办？下一课讲索引工程，从数据源头解决这些问题。

# 第 2 课：索引工程 —— 真实文档来自网页、PDF、Word，怎么解析和索引？（40 分钟）

> **本课目标**：攻坚生产环境最痛苦的数据入库与索引工程，掌握多源文档解析、内容分类路由、Parent-Child 父子切片与知识图谱索引。

### 1. 真实世界的暴击：数据入库七重山（00:00 - 12:00）
- **现实没有干净 Markdown**：供应商扫描件 PDF 质检单、乱序双栏、跨页大表与带错别字的买家 Review；
- **多源文档解析**：
  1. MinerU / LayoutLM 版面分析：按自然阅读顺序重组双栏文本，消除 OCR 字符粘连与乱码；
  2. Table Header Injection（动态表头注入）：跨页大表切片后，为每一行子切片动态拼装完整表头；
  3. 买家 Review 评论蒸馏：用 LLM 剔除情绪化废话，提纯"偏小半码/略微透光"原子级知识；
  4. PII 隐私脱敏：买家身材信息与私人地址自动化掩码脱敏，符合 GDPR 合规。

### 2. 层次化切片工程：Parent-Child 父子切片与句子窗口（12:00 - 26:00）
- **传统分块的永恒矛盾**：
  - 小切片（128 tokens）：语义精准，但丢失上下文，大模型答非所问；
  - 大切片（1024 tokens）：上下文完整，但向量表示被泛化稀释，命中率暴跌；
- **破局方案 A：Parent-Child（Small-to-Big）父子切片架构**：
  - 索引端：对 128-token 的 Child Chunks 进行 Embedding 并存入向量库；
  - 检索端：命中 Child Chunk 后，自动映射回滚其所属的 1024-token Parent Chunk 喂给大模型；
- **破局方案 B：Sentence Window Retrieval（句子窗口回溯）**：
  - 单句精准向量命中 → 动态扩展前后 K 个句子窗口作为上下文装箱。

### 3. 知识图谱索引与生产级向量索引调优（26:00 - 40:00）
- **多模态知识图谱索引**（参考 RAG-Anything）：
  - 把图片/表格/公式转成知识图谱实体节点；
  - 建立跨模态关系（belongs_to 层级链）；
  - 向量-图融合检索：向量相似度搜索 + 图遍历，两种方式互补；
- **HNSW（分层可导航小世界）图索引调优**：
  - 核心参数：M（邻居数）、efConstruction（建图深度）、efSearch（在线检索精度与 QPS 权衡）；
- **本课小结**：打牢数据与索引地基，下一课进入检索优化与重排。

# 第 3 课：高级RAG —— 纯检索还是不够准，怎么进一步提升？（40 分钟）

> **本课目标**：直击检索结果质量瓶颈，深入掌握查询改写、Cross-Encoder 重排、上下文装箱与论文 Best Practice 黄金组合。

### 1. 查询改写：用户说的和大模型懂的不是一回事（00:00 - 10:00）
- **事故复盘**：买家问"遮肉"、选品搜"老钱风"，和严肃工业质检参数之间存在词汇鸿沟；
- **Query Rewrite**：基于轻量小模型改写查询，将"老钱风开衫"拓展为"100% 澳大利亚美利奴羊毛 16 针高密精纺"；
- **Multi-Query**：多路并发拓展，一个查询变多个子查询同时检索。

### 2. Cross-Encoder 深度重排（10:00 - 22:00）
- **事故复盘**：2023 废止偏小尺码表因词频密集抢占 Top-1，男款 40" 直筒串线推给女款；
- **机制剖析**：Bi-Encoder 双塔各自编码，缺乏 Token 交叉注意力，无法识别时效与修饰关系；
- **两步破局**：
  1. Metadata 预过滤：`status == 'Active' AND department == 'Women'` 物理阻断；
  2. Cross-Encoder 深度重排：Query 与 Doc 拼接送入 Transformer 做 Full Self-Attention 交叉打分。

### 3. 上下文装箱与 Lost in the Middle（22:00 - 30:00）
- **事故复盘**：跨页大表中包含 Petite 28" / Regular 31" Inseam，塞在 Prompt 中间被大模型漏看；
- **破局**：
  - Reverse 反向排布：最高分切片紧贴 Prompt 末尾的 Query；
  - Adjacent Chunk Merging：相邻碎片切片自动平滑缝合，XML 标签结构化包裹。

### 4. 论文 Best Practice：arXiv:2407.01219 黄金组合（30:00 - 40:00）
- **顶会消融实验结论**：
  1. Chunking：512 tokens + 10% Overlap 配合句子窗口最稳健；
  2. 检索底座：BM25 + Dense 混合检索 (RRF, k=60) 是性价比基石；
  3. ROI 最高的单一模块：Cross-Encoder Reranker；
  4. 最被低估的高效技巧：Reverse Context Repacking；
- **本课小结**：四项工程组合拳构建了检索与装箱的最强防线。

# 第 4 课：多模态RAG —— 商品图片、尺码表、面料图都是视觉内容，纯文本RAG完全搜不到（40 分钟）

> **本课目标**：掌握跨模态向量编码、多模态内容解析与融合，落地电商以图搜款与图文组合搜索。

### 1. 痛点：纯文本 RAG 的视觉盲区（00:00 - 08:00）
- 商品详情页的产品图、嵌在 PDF 里的尺码表、面料微距图——纯文本 RAG 对这些完全无能为力；
- 多模态 RAG 的定义：在检索和生成阶段同时处理多种模态（文本、图像、表格），利用跨模态线索增强事实基础。

### 2. 跨模态向量编码（08:00 - 18:00）
- CLIP / FashionSigLIP：把图片和文本映射到同一个向量空间；
- 跨模态对齐的核心挑战：不同模态的语义空间天然不对齐。

### 3. 多模态内容解析与融合（18:00 - 28:00）
- 参考 RAG-Anything：文档解析 → 内容分类路由（文本/图片/表格/公式分别处理）→ 多模态知识图谱索引 → 模态感知检索；
- 上下文感知：处理图片时自动抽取周围文本作为上下文，让模型理解图片在文档中的位置和含义。

### 4. 电商实战：以图搜款与图文组合搜索（28:00 - 38:00）
- **以图搜款（Image-to-Image）**：买家上传街拍图，毫秒级召回视觉最相似 Listing；
- **图文组合搜索（Composed Search）**：图片 + 文字修饰（"同款版型，但换成军绿色加侧兜"）；
- **VLM 视觉质检**：多模态大模型对微距面料纹理与拉链细节做视觉判定。

### 5. 本课小结（38:00 - 40:00）
- 多模态 RAG 不只是以图搜图，核心是让 RAG 能理解和检索非文本内容。

# 第 5 课：AgenticRAG —— 固定管线搜一次就交给大模型，复杂问题一次搜不全（40 分钟）

> **本课目标**：从固定管线 RAG 演进到 Agent 自主检索，掌握 Self-RAG/CRAG 自纠正过渡与 AgenticRAG 工具化迭代检索。

### 1. 固定管线的天花板（00:00 - 08:00）
- 标准 RAG：检索决策在推理之前就固定了，LLM 只能"看给什么用什么"；
- 真实企业查询是复杂的：需要多轮搜索、跨文档导航、迭代精化。

### 2. 过渡形态：Self-RAG 与 CRAG（08:00 - 18:00）
- **Self-RAG**：模型自己判断要不要检索、检索结果相不相关；
- **CRAG（Corrective RAG）**：检索结果不好就纠正/重搜；
- 这是从"固定管线"到"Agent 自主"的中间形态。

### 3. AgenticRAG：给 LLM 配工具（18:00 - 32:00）
- 参考 arXiv:2605.05538：给 LLM 配上 search、find、open、summarize 工具；
- LLM 自主决定搜什么、什么时候搜、在文档里怎么跳转，迭代式检索和推理；
- 实测比单次检索提升 5.9 倍；
- 设计要点：agentic loop 算法、系统指令、工具使用模式。

### 4. 失败模式与工程边界（32:00 - 40:00）
- 常见失败模式：工具滥用、无限循环、上下文爆炸；
- 工程约束：最大迭代次数、Token 预算、工具调用审计。

# 第 6 课：结果评估 —— 如何杜绝幻觉？（40 分钟）

> **本课目标**：建立 RAG Triad 三维量化评测体系与自动化测试门禁。

### 1. 拒绝凭感觉评估（00:00 - 10:00）
- 为什么需要量化评估：不能只看"回答看起来对不对"。

### 2. RAG Triad 正交解耦（10:00 - 24:00）
- **Context Relevance（检索相关度）**：召回片段中有效信息密度，消除噪音；
- **Faithfulness（事实忠实度）**：答案能否被证据严格逻辑证明——服饰出海第一死线；
- **Answer Relevance（答案契合度）**：是否直接命中用户提问；
- NLI 形式化证明：将回答拆解为原子断言，逐一验证蕴含关系。

### 3. 自动化测试与上线把关（24:00 - 34:00）
- 500 道服饰箱包 Golden Dataset 回归测试流水线；
- 质量红线：Faithfulness 必须达到 100%，历史废弃版本零泄露，否则阻断发布；
- 线上可观测性：全链路 Trace，抓取低置信度 Bad Case，清洗后回流训练集。

### 4. 总结升华（34:00 - 40:00）
- 用确定性的工程体系约束概率大模型，守护商业生命线。

# 第 7 课：案例解读与技术展望 —— 业界真实落地长什么样？下一步往哪走？（40 分钟）

> **本课目标**：解读开源项目与公开落地案例，补充 Text2SQL 等技术，展望 RAG 未来方向。

### 1. 开源项目案例解读（00:00 - 15:00）
- RAGFlow、Langchain-Chatchat、RAG-Anything、LightRAG 等开源项目的架构对比与落地经验。

### 2. 公开落地案例（15:00 - 25:00）
- 电商视觉搜索（京东、eBay）、企业知识库问答、金融文档分析等真实案例。

### 3. 补充技术：Text2SQL 与结构化数据检索（25:00 - 32:00）
- 电商核心数据是结构化表（价格、库存、尺码），纯向量检索处理不了精确过滤；
- Text2SQL：让自然语言直接查数据库，与 RAG 形成互补。

### 4. 未来方向（32:00 - 40:00）
- 统一多模态嵌入空间、Agent 长期记忆、跨模态可解释性、安全与隐私。
