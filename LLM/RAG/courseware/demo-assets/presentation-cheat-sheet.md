## 二、 试讲全场“三大不能犯的低级错误”（防翻车清单）

1. **绝对不要做长时间 live coding 或现场 pip install**：
   - 依赖网络和环境随时会翻车。所有代码、数据库、模型推理必须是预先封装好的脚本或一键运行的 Jupyter Notebook 单元格，现场只展示核心数据结构、打分矩阵和输出差异。
2. **绝对不要一味罗列术语名词**：
   - 每抛出一个高级概念（如 Hybrid / ColPali / GraphRAG / Rerank / Semantic Router），必须先讲出它对应的**业务痛点**（如“专有名词搜不到”、“带电标签图片看不懂”、“多系统意图跑偏”、“跨文档关系推理不出”），再给出技术名词。
3. **绝对不要只展示‘答对了’，必须展示‘错在哪’**：
   - 听众对成功的 Demo 已经麻木了。真正能建立专家权威的，是把 DOC-004（废止版）为什么余弦相似度高达 0.89 剖析给他们看，让他们心服口服。

## 三、 贯穿全场的“专家金句”提气速查表

- **开场**：*“市面上 90% 的教程都在教你用 10 行代码跑通 Demo；但真实工业落地，这 10 行代码上线第一天就会导致店铺封禁。”*
- **中盘**：*“RAG 的核心首先不是生成，而是信息检索；垃圾进，垃圾出。向量相似度衡量的是语义表达的接近，而不是业务逻辑的正确。”*
- **解法**：*“没有单一检索范式能包打天下。结构化约束靠 Metadata，精准词匹配靠 BM25，语义模糊靠 Dense，终极排序靠 Cross-Encoder，破除注意力黑洞靠 Reverse Repacking 上下文装箱。”*
- **尾盘**：*“没有解耦评测的调优，就像蒙着眼睛修发动机。工业级 RAG 绝不靠‘感觉不错’，靠的是自动化 CI/CD 质量门禁与 Bad Case 数据飞轮。”*
